# Localify Music API 2.1

FastAPI запускается на отдельном сервере. Android отправляет туда поисковый запрос и получает адрес разрешённого потока или скачивания. Аудиобайты телефон получает непосредственно с официального адреса источника. Секрет доступа к серверу не передаётся источнику. В APK нет заранее заданного сервера, ключа или токена VK.

## Источники и проверка

- **Audius** включён по умолчанию. Анонимный публичный REST API используется для песен, исполнителей и альбомов. Аудио доступно при разрешении публичного потока. Скачивание появляется, только если API одновременно подтверждает явное разрешение, доступ анонимному пользователю и отсутствие ограничения. Сервер проверяет разрешение повторно перед выдачей ссылки. Не все треки популярных исполнителей представлены. [Документация API](https://docs.audius.co/api/).
- **VKpyMusic 4.0.2** изучен по исходникам `d4b6e6e` и установлен из PyPI. Реальный вызов `search_songs_by_text_async` без токена получил `VkApiException 15`; прямой ответ `audio.search` также сообщил, что нужен токен. Проверить авторизованный запрос было невозможно. Необязательный адаптер использует этот метод для метаданных, когда оператор установил `VK_CATALOG_TOKEN` с разрешённым доступом. Воспроизведение и скачивание из VK в сборке недоступны: поле URL не подтверждает право третьего приложения получать аудио. [VKpyMusic](https://github.com/issamansur/vkpymusic).
- **vk-music-bot-api** изучен по исходникам `9b4cac8`. Telegram InitData авторизует пользователя мини-приложения, а не доступ к музыке VK. Поиск использует отдельный VK-токен и `audio.search`, получение ссылки вызывает `get_songs_by_id`. Его маршруты загрузки не перенесены. [vk-music-bot-api](https://github.com/TraftG/vk-music-bot-api).

В интеграционной проверке FastAPI обращался к реальному Audius. Проверены кириллица и латиница, разрешённое скачивание MP3 (4 609 965 байт, первый аудиофрейм декодирован), Range-ответ потока (HTTP 206, аудиобайты) и отказ скачивания для трека с ограничением (HTTP 403). Тесты с подменёнными провайдерами используются только для отдельной проверки ошибок, авторизации, сортировки, устранения дублей и запрета доступа.

## Oracle Cloud Always Free

Понадобятся учётная запись Oracle Cloud и DNS-имя, которым вы управляете. В домашнем регионе создайте Ubuntu VM с публичным IPv4 на форме, помеченной в консоли как **Always Free eligible**. Для этого API достаточно одной небольшой ВМ. На ARM используйте Docker Engine и Compose плагин для ARM64. При отсутствии ёмкости A1 рассмотрите другую доступную форму с отметкой Always Free. Лимиты и правила неактивности смотрите в [документации Oracle](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

1. Установите [Docker Engine и Compose для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Включите запуск Docker после перезагрузки: `sudo systemctl enable --now docker`.
2. В DNS добавьте A-запись на публичный IP. Откройте входящие TCP 80 и 443 в OCI Security List или NSG и в системном брандмауэре. SSH 22 оставьте доступным только с разрешённого IP. Порт 8000 публиковать не нужно.
3. Скопируйте содержимое этого архива на ВМ. В каталоге с `compose.yaml` создайте локальный файл настроек:
   ```sh
   umask 077
   cp .env.example .env
   openssl rand -hex 32
   ```
   Запишите полученное значение в `LOCALIFY_API_KEY`, а своё доменное имя без схемы в `LOCALIFY_DOMAIN`. Передавайте ключ только доверенным пользователям. Оставьте `INSTALL_VK=0`, если нужна рабочая конфигурация по умолчанию.
4. Запустите `sudo docker compose up -d --build`. Caddy получает TLS-сертификат при корректном DNS и открытых портах. Контейнеры настроены на `restart: unless-stopped`. TLS-данные сохраняются в томе.
5. Проверьте `curl -fsS https://ВАШ_ДОМЕН/healthz`. Ответ `{"status":"ok","api":1}` подтверждает, что сервер доступен. Для просмотра состояния используйте `sudo docker compose ps` и `sudo docker compose logs --tail=50 music caddy`.

## Альтернатива на Render

Разместите содержимое backend-архива в корне своего репозитория. Создайте бесплатный сервис из `render.yaml` как Blueprint или выберите **Web Service → Docker** и задайте `/healthz` в Health Check Path. Если код находится в полном репозитории Localify, укажите `server` как корневой каталог сервиса. Задайте `LOCALIFY_API_KEY` как переменную среды, либо возьмите значение, созданное Blueprint, из настроек Render. Укажите полученный HTTPS-адрес `*.onrender.com` на телефоне. Бесплатный сервис засыпает при простое. Для длительно доступного сервера используйте OCI или тариф Render без засыпания. [Ограничения Render Free](https://render.com/docs/free).

## Подключение Android

В Localify 2.1 откройте **Поиск → Онлайн → ⚙**. Введите HTTPS-адрес без пути и ключ из `LOCALIFY_API_KEY`. Нажмите «Проверить и сохранить». После соединения выберите «Песни», «Исполнители» или «Альбомы». Через раздел «Загрузки» виден прогресс и доступна отмена. Сохранённые файлы доступны в медиатеке без сети.

Ключ хранится зашифрованным с помощью Android Keystore. В запросах к бэкенду ключ передаётся в заголовке Authorization, а перенаправления на этой границе запрещены. Сервер хранит хеш ключа для проверки, ограничивает частоту и число параллельных запросов, кэширует выдачу и не пишет заголовки, поисковые строки или токены в журнал. В схеме с обратным прокси сервер видит его адрес, поэтому лимит применяется совместно для запросов через этот прокси.

Android проверяет заявленный размер файла, формат, наличие аудиодорожки и SHA-256, если источник его возвращает. Полученный без размера и контрольной суммы файл не сохраняется. Действующий токен VK при необходимости настраивается **только** как переменная среды сервера. Для такого деплоя включите `INSTALL_VK=1` при сборке Docker и задайте `VK_CATALOG_TOKEN`. Сервер не запрашивает пароль пользователя VK.

## Запуск и тесты

Нужен Python 3.12 или новее. Установите `python -m pip install -r requirements-dev.txt` и выполните `python -m pytest -q`. Для локального запуска установите `LOCALIFY_API_KEY` в среде и запустите `python -m uvicorn app:app --host 127.0.0.1 --port 8000 --no-access-log`. Этот HTTP-адрес только для локальных проверок; Android требует HTTPS. Маршруты API: `GET /healthz`, `GET /v1/status`, `GET /v1/search?q=...&scope=track|artist|album`, `GET /v1/tracks/{id}/stream` и `GET /v1/tracks/{id}/download`. Два последних маршрута возвращают JSON с официальным URL после проверки прав доступа.
